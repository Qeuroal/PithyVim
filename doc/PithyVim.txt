PithyVim is a personal Neovim configuration built on lazy.nvim.  It keeps the
the familiar lazy.nvim module layout while adding Qeuroal's editor defaults,
Markdown/Notebook support, and local test coverage.


FEATURES                                                    *PithyVim-features*

- Lazy-loaded plugin specifications with optional language and UI extras
- Catppuccin, TokyoNight, Everforest, and OneDarkPro color scheme registry
- Snacks, Telescope, or FzfLua based picker workflows
- Tree-sitter highlighting, folds, indentation, and parser compatibility checks
- LSP, formatting, linting, DAP, completion, snippets, and AI integrations
- Markdown images and math rendering, including multiline LaTeX source reveal
- Jupyter Notebook facade for `ipynb` files
- VimTeX with Skim synchronization support
- Tmux pane navigation, alignment tools, ANSI rendering, and UndoTree
- Offline mini.test regression and configuration-contract tests


REQUIREMENTS                                            *PithyVim-requirements*

- Neovim >= **0.11.2** (built with **LuaJIT**)
- Git >= **2.19.0**
- A Nerd Font <https://www.nerdfonts.com/> **(optional)**
- A C compiler for nvim-treesitter
- `rg` for source checks and grep pickers
- `tree-sitter` CLI >= **0.26.1** for automatic LaTeX parser installation
- `latexmk` and Skim **(optional, for TeX extras on macOS)**
- A terminal with image support **(optional, for Snacks images and math)**


GETTING STARTED                                      *PithyVim-getting-started*

Clone this repository as your Neovim configuration:

>sh
    mv ~/.config/nvim ~/.config/nvim.bak
    git clone https://github.com/Qeuroal/PithyVim ~/.config/nvim
    nvim
<

The repository's `init.lua` loads `pithyvim`.  Plugins are installed by
lazy.nvim on first start.  To run the local test suite:

>sh
    make test
<

The test command can also be run from outside the repository:

>sh
    /path/to/PithyVim/scripts/test --offline
<

To copy Lua sources into a local Lazy installation:

>sh
    make local
<

The `make gitmerge` target merges `dev` into `master` and pushes it.  Review
that target before using it because it changes branches and remote state.


FILE STRUCTURE                                        *PithyVim-file-structure*

    init.lua                         Entry point
    lua/pithyvim/config/              Options, autocmds, keymaps, setup
    lua/pithyvim/plugins/             Core plugin specifications
    lua/pithyvim/plugins/extras/      Optional language and feature specs
    lua/pithyvim/util/                Shared helpers and plugin utilities
    queries/lua/                      Custom Tree-sitter queries
    tests/                            mini.test specs and regression checks
    scripts/test                      Test runner
    Makefile                          Local install, test, and merge targets
    doc/PithyVim.txt                  This help file

Files under `lua/pithyvim/config/` are loaded by the PithyVim setup.  Plugin
specifications are imported by lazy.nvim.  User plugin overrides can be put
in the user's own `lua/plugins/` directory.


DEFAULTS                                                *PithyVim-defaults*

PithyVim defaults are defined in `lua/pithyvim/config/options.lua`.

- Automatic formatting is disabled by default (`vim.g.autoformat = false`).
- Diagnostics are disabled by default and can be toggled with `<leader>ud`.
- Indentation effectively uses four spaces: `tabstop=4`, `shiftwidth=0`
  inherits `tabstop`, and `softtabstop=-1` inherits `shiftwidth`.
- Mouse input and invisible-character display are disabled.
- Wrapping is enabled, `linebreak` is disabled, and `textwidth` is zero.
- Folding starts disabled with `foldmethod=indent`; marker folds use `{{{>,<}}}`.
- Persistent undo files are stored below the PithyVim/Neovim cache directory.
- `virtualedit` includes `block` and `onemore`.
- Diff mode uses `followwrap`, `context:3`, `algorithm:patience`, and
  `indent-heuristic`.
- Markdown, text, TeX, Typst, and Git commit buffers wrap without spell check.

`CamelToSnake` and `SnakeToCamel` are range commands for converting selected
lines.  `PITHYVIM_CACHE_DIR` can override the cache directory used by helpers.


KEYMAPS                                                    *PithyVim-keymaps*

The following are the main PithyVim additions.  Plugin-specific mappings are
also shown by `:LazyExtras` and WhichKey.

    <C-s>                 Save without leaving the current mode
    <leader>ll             Open Lazy
    <leader>le             Open LazyExtras
    <leader>fy             Copy the current file path
    <leader>fY             Copy the current directory path
    <leader>cE             Show effective EditorConfig rules and files
    <leader>xw             Open the error Quickfix list on the right
    <leader>qw             Save and quit all windows
    <leader>tz             Toggle marker/expr foldmethod
    <leader>tc             Toggle system clipboard integration
    <leader>ti             Toggle Snacks image rendering
    <leader>tm             Toggle Snacks math rendering
    gy                     Yank to the system clipboard
    gp                     Paste from the system clipboard
    gP                     Paste before from the system clipboard
    <leader>uS             Toggle Snacks smooth scrolling
    <leader>uu             Toggle UndoTree

Lowercase picker mappings generally use the current working directory or
current buffer.  Uppercase variants generally use the project root or
workspace.  This applies to file search, grep, word search, and diagnostics.

The optional Tmux navigation extra assigns `<C-h>`, `<C-j>`, `<C-k>`, and
`<C-l>` to cross Neovim windows and Tmux panes.  `<C-\>` goes to the last
active pane and `<C-Space>` goes to the next pane.


COLOR SCHEMES                                          *PithyVim-colorschemes*

The registry is in `lua/pithyvim/config/colorscheme.lua`.  The default is
Catppuccin Macchiato.  Available registry entries are:

- `catppuccin`
- `tokyonight`
- `everforest`
- `onedarkpro`

Catppuccin customizes `WinSeparator` with a blue foreground and transparent
background.  The theme loader setup is controlled by `PithyVim.config`.


PICKERS AND UI                                          *PithyVim-pickers*

PithyVim supports picker extras for Snacks, Telescope, and FzfLua.  Their
common behavior is:

- cwd/root scope follows the lowercase/uppercase convention above
- diagnostics distinguish workspace and current-buffer views
- hidden files are enabled in the Snacks file and grep sources
- Snacks file search does not follow symbolic links
- Snacks picker uses `<C-c>` to close, `<C-j/k>` for selection, and
  `<C-n/p>` for history
- Git restore in Snacks requires the two-key sequence `<C-r><C-r>`

Explorer extras configure left-side layouts, preview panes, hidden files, and
diagnostic visibility.  `mini-align` provides `ga` and `gA`; `align.nvim`
provides `aa`, `ad`, `aw`, `ar`, `gaw`, and `gaa`.  The ANSI renderer extra
automatically handles `log` and `ansi` buffers.

LIVE GREP TWO-STAGE SEARCH                         *PithyVim-live-grep-search*

`<leader>/` uses Snacks Picker to search the current working directory in two
stages.  Live mode sends the input to ripgrep as a regular expression:

>text
    foo              Match foo
    foo|bar          Match foo or bar
    ^local           Match lines starting with local
    TODO$            Match lines ending with TODO
    foo -- -w        Match the complete word foo
    foo -- -g=*.lua  Search only Lua files
<

Use `<A-r>` to toggle between regular-expression and literal search.  Press
`<C-g>` to leave Live mode and filter the existing results with the
FZF-compatible Snacks matcher:

>text
    foo bar   Include both foo and bar
    'foo      Include the exact term foo
    ^foo      Start with foo
    bar$      End with bar
    !test     Exclude test
    foo | bar Match foo or bar
<

Press `<C-g>` again to return to Live Grep.


COMPLETION AND SNIPPETS                              *PithyVim-completion*

Blink and nvim-cmp use `<C-j/k>` for candidate navigation.  Blink additionally
uses `<C-l>` for documentation, `<C-y>` to accept, `<C-e>` to hide, and
`<C-b/f>` to scroll documentation.  Tab and S-Tab move through snippets.

LuaSnip automatically loads snippets from:

    ~/.config/nvim/snippets/from_vscode
    ~/.config/nvim/snippets/from_snipmate

Snippet history is disabled and S-Tab only jumps when a backward jump is
available.  Function and method completions avoid adding duplicate parentheses
and safely handle end-of-line completion.


AI                                                    *PithyVim-ai*

Copilot attaches to all filetypes except sensitive filenames containing
`cookie`, `.env`, `token`, `secret`, `credential`, or `config` patterns.
Blink Copilot settings are merged with existing completion providers.

When Sidekick reports `Completions limit reached`, PithyVim disables Sidekick
NES and shows a single warning instead of repeatedly reporting the same error.


MARKDOWN AND NOTEBOOKS                              *PithyVim-markdown*

Snacks image and math rendering are disabled by default.  Use `<leader>ti`
and `<leader>tm` to toggle them independently.  Defaults can be overridden
with `image.enabled` and `image.math.enabled` in the user's `.lazy.lua` opts.
`force=false` keeps rendering dependent on terminal support.

With math enabled, inline updates pause in Insert mode and refresh on
InsertLeave.  When the cursor enters a multiline rendered formula, concealed
lines are revealed so the full LaTeX source can be edited.  Image modules are
loaded only when either renderer is enabled.

The LaTeX Tree-sitter parser is requested only when the system `tree-sitter`
CLI is version 0.26.1 or newer.  This avoids ABI and GLIBC failures on older
servers.  Render-markdown's own LaTeX renderer is disabled to avoid duplicate
rendering; headings, code blocks, checkboxes, images, and math remain
available through the configured renderers.

The Jupyter extra is recommended for both an `ipynb` filetype and filenames
ending in `.ipynb`.  It connects `ipynb.nvim` with Tree-sitter, LSP,
render-markdown, and Snacks images.  Markdown rendering is attached to the
`ipynb` filetype with `anti_conceal.enabled=false`.


TEX AND LANGUAGE EXTRAS                                *PithyVim-tex*

The TeX extra is recommended when `latexmk` is executable.  VimTeX uses Skim,
supports forward/reverse synchronization, disables automatic viewer opening,
and disables its built-in completion and insert mappings.  Sections,
ligatures, citations, accents, and text styles remain concealed.  VimTeX math
symbols, delimiters, fractions, superscripts, and subscripts are not concealed
to avoid overlapping with Snacks math rendering.

The Python extra is also recommended when `python` or `python3` is executable.
All language extras expose a `recommended` condition and can be enabled with
the LazyExtras UI.


TREE-SITTER AND LSP                                  *PithyVim-treesitter*

Tree-sitter parser availability is checked directly on the runtimepath with
`PithyVim.treesitter.have_parser()`.  Concurrent CLI installation requests
share one Mason installation and notify all waiting callbacks.

Tree-sitter highlighting, indentation, and folding are enabled only when the
language parser and query are available.  `<leader>cL` restarts the active LSP.


TESTING                                                  *PithyVim-testing*

Run the complete offline suite with:

>sh
    scripts/test --offline
<

The suite checks plugin specs, language recommendations, parser duplication,
renamed plugins, memoization, completion edge cases, runtime parser detection,
Snacks image and math toggles, EditorConfig indentation inheritance, Markdown
multiline source reveal, Tree-sitter CLI version gates, and Jupyter
recommendation conditions.

The current suite is expected to report 450 cases and 5 groups, with zero
failures.


CONFIGURATION                                          *PithyVim-configuration*

Use `lua/pithyvim/config/options.lua` for editor options, autocmds for buffer
behavior, and keymaps for global mappings.  Use plugin extras for optional
features instead of editing their upstream plugin defaults.

PithyVim-specific settings are grouped with `--{{{> Qeuroal` and `--<}}}`
markers in Lua files.  Keep new personal changes in the same marked style.
